# Kopilia : le guide détaillé

> Pour installer Kopilia, commence par le [README](../README.md). Ce guide décrit tout le reste : chaque fonction, l'architecture et les choix techniques.

Assistant vocal **français**, 100 % local pour l'audio, piloté par le CLI **Claude Code**, sur Mac Apple Silicon. On lui parle en maintenant une touche, comme un talkie‑walkie, et l'assistant **Kopilia** répond avec la voix **ff_siwis** (Kokoro‑82M). On peut lui parler pendant qu'il répond (une autre demande passe après sa réponse, « stop » le coupe), on poursuit la conversation avec son contexte, et lui confier des tâches dans ses projets (les sous‑dossiers de `~/Documents`) pendant qu'on continue à parler.

- Le Mac traite l'audio (STT **whisper.cpp**, TTS **Kokoro**).
- Claude reçoit le **texte** (et, pour les tâches autorisées, le contexte du projet). L'inférence de Claude exige une connexion Internet.
- Tout est sur **loopback** (127.0.0.1) ; rien n'est exposé au réseau.
- **Noms.** *Kopilia* est le nom technique du projet (paquets `@kopilia/*`, variables `KOPILIA_*`, base `kopilia.sqlite`) ; *Kopilia* est celui de l'assistant, le seul qu'on voit et qu'on entend.

> **État de cette base.** La colonne vertébrale est construite **et vérifiée** : boucle texte Nest ↔ Claude (rappel « Atlas » sur deux tours), transport WebSocket + audio binaire, synthèse par phrases, barge‑in, idempotence, persistance SQLite + reprise, mémoire FTS5, coordination de tâches par MCP. La couche audio (whisper/Kokoro) et le branchement final à l'**authentification** du CLI se terminent sur votre Mac via `pnpm run setup` (voir [docs/RECIPE.md](RECIPE.md) pour ce qui reste à faire physiquement).

## 2. Installation (une fois)

```bash
pnpm run setup
```

> `pnpm run setup` (avec `run`) : `pnpm setup` seul est une commande **intégrée** de pnpm qui configure pnpm lui‑même, pas notre script. `pnpm bootstrap` fonctionne aussi.

Le bootstrap (relançable) : détecte l'outillage, installe les dépendances, **compile** contracts + serveur + web, **compile whisper.cpp** (Metal), crée le **venv Kokoro**, **télécharge** les modèles (manifeste vérifié, reprise sans re‑téléchargement), **synthétise une phrase de contrôle**, puis lance `doctor`. Si un geste système est requis (Xcode, `claude login`), il l'indique précisément et vous relancez.

```bash
pnpm doctor   # état : outillage, modèles, voix FR, workers, port, CLI, auth
```

## 3. Démarrage quotidien

```bash
pnpm start
```

Ouvrez **http://127.0.0.1:4317** : la connexion est automatique (et se rétablit seule si le serveur redémarre). Pour lui parler, **maintiens ⌥ droite** (Option droite), parle, puis lâche : comme un talkie‑walkie, ni bouton à décrocher, ni micro à couper. Le premier geste dans la page (un clic, une touche) autorise le son et ouvre le micro, une fois par chargement ; ensuite, rien ne quitte le navigateur tant que la touche n'est pas tenue. En bas de l'écran, il ne reste que **Joindre** :
- **⌥ droite seule** : ta phrase commence après 0,2 s sans autre touche (sinon c'était un raccourci, ⌥ A ou un caractère ⌥ (, et rien ne se passe) ; les 0,3 s d'avant l'appui sont gardées, le premier mot n'est pas perdu. **⌥ Espace** (l'un ou l'autre ⌥) fait la même chose, tout de suite ;
- **lâcher envoie aussitôt** : pas d'attente de silence, et une phrase qui a l'air inachevée part telle quelle (relâcher dit qu'elle est finie). Une phrase part d'elle‑même au bout de 60 s, ou si la fenêtre perd le clavier (dans le navigateur) ; une autre touche pendant l'appui l'annule ;
- **lâcher sans rien dire le fait taire** : un appui bref sur ⌥ droite, ou un appui sans parole (le détecteur de voix Silero en juge, Whisper ensuite), coupe ce que Kopilia dit ou prépare ;
- **depuis une autre application (TradingView devant)** : une page ne voit le clavier que quand elle l'a. Pour parler à Kopilia où que tu sois, ouvre-le dans **l'application Kopilia** (voir plus bas) plutôt que dans le navigateur ;
- **tu peux parler pendant qu'il répond** : dès l'appui, Kopilia se met en pause, le temps de ta phrase.
  - Une autre demande (« ouvre le graphique du Nasdaq » pendant le résumé du brief) ne coupe rien : il reprend là où il s'était arrêté, ta demande est traitée tout de suite (le graphique s'ouvre à l'écran), et sa réponse est dite et affichée juste après la sienne. Si tu parles dans les premières secondes, pendant qu'il rédige encore, ta demande attend la fin de la rédaction.
  - **Pour le couper**, commence ta phrase par « stop », « attends », « arrête », « tais‑toi », « chut », « ça suffit », « laisse tomber » ou « non » (« Attends, plutôt l'or »). Sa réponse, et celles qui attendaient derrière elle, sont abandonnées, et il sait qu'il a été interrompu. « Stop loss… » et « Non farm… » ne coupent pas. Un « stop » isolé est court : « stop, stop » ou « attends » passent mieux, et toucher l'orbe coupe aussi. La liste est dans [`transcript-filter.ts`](../apps/server/src/voice/transcript-filter.ts).
- **des mots mal compris ?** Ajoute‑les dans `config/vocabulaire.txt`, ton fichier, créé à l'installation à partir du [modèle](../config/vocabulaire.example.txt) et jamais envoyé sur GitHub : un terme par ligne (noms propres, sigles, projets), plus un mot de contexte si besoin (« Fed » avec « taux directeurs »). Pour une erreur qui persiste, ajoute une ligne `erreur => correction` (par exemple `Copilia => Kopilia`). C'est pris en compte en 30 s, sans redémarrer. Garde la liste courte : chaque terme en trop dilue les autres ;
- **le texte suit la voix** : la réponse s'écrit mot à mot pendant que Kopilia la dit, jamais avant. Chaque phrase est calée sur le début de son audio (latence du casque comprise), puis révélée au prorata de sa durée. Pendant une pause (tu prends la parole), le texte s'arrête avec la voix. Une réponse qui attend son tour s'affiche quand la précédente a fini de se dire. Si tu coupes Kopilia, le reste s'affiche d'un coup. Avant le premier geste dans la page, ou si la voix est en panne, le texte s'affiche dès qu'il arrive ;
- **écrit pour l'écran, transcrit pour la voix** : l'écran garde le texte écrit (« 16h », « 4,85 % », « le PMI »), et la voix reçoit une version faite pour être bien dite, dans [`spoken-french.ts`](../apps/server/src/voice/spoken-french.ts). Kokoro lirait sinon « seize ache », « quatre… quatre‑vingt‑cinq », « pmi ».
  - Réécrits : les heures (« 16 heures 30 », « une heure »), la virgule et le signe moins, les montants (« 4 euros 50 », « 1 virgule 2 milliard d'euros »), K/M/B du calendrier, les points de base, m/m et y/y (« sur un mois », « sur un an »), les dates (« 2 novembre 2026 »), les ordinaux et trimestres (« deuxième », « troisième trimestre »), les unités (« kilomètres heure », « 12 degrés »), « vs », « n° », « M. ».
  - Les sigles sont épelés (« P M I »), sauf ceux qui se disent comme des mots (OPEP, OTAN, CAC…). Les émojis ne sont pas lus.
  - Pour une nouvelle erreur de prononciation, une règle s'ajoute dans ce fichier ; on vérifie les phonèmes avec `KPipeline(lang_code="f", model=False).g2p(texte)` dans le venv Kokoro ;
- **l'orbe central est une sphère de points** (canvas, [`dot-sphere.ts`](../apps/web/src/app/orb/dot-sphere.ts)) qui tourne lentement au repos et s'anime dès qu'il se passe quelque chose : elle verdit et respire quand tu parles (touche tenue), des vagues parcourent sa surface et elle gonfle avec la voix de Kopilia (en bleu), elle s'agite et accélère quand il réfléchit. Le **toucher l'interrompt** aussi, en secours si l'écho des haut‑parleurs gêne (avec un casque, aucun souci).
- **une galaxie de neurones occupe tout l'écran** derrière l'orbe, qui en est le cœur, et montre où en est Kopilia :
  - au repos, un ciel d'étoiles, des nébuleuses et des bras spiraux de neurones tournent lentement, très discrets ;
  - quand il réfléchit, la galaxie s'embrase : elle tourne plus vite, des influx courent d'un neurone à l'autre et les allument ;
  - chaque étape de sa réponse (recherche web, calendrier, agent dépêché…) fait naître un petit nœud nommé autour de l'orbe ;
  - chaque agent ou tâche en cours est un neurone relié à l'orbe, nommé par son projet (trois projets en parallèle, trois neurones), entouré d'un bloc par étape faite, avec la dernière (« 6 étapes · Recherche web ») ;
  - couleurs : vert pour un agent, bleu pour une tâche, orange en attente de ton accord ; en finissant, le neurone clignote vert (rouge en cas d'échec), puis s'efface.
  - Avec « réduire les animations » dans les réglages du Mac, la galaxie reste immobile.
- **la discussion s'affiche discrètement en bas à droite** (au-dessus des boutons sur un écran étroit) : chaque échange apparaît en fondu, l'ancien texte s'efface par le haut, et elle pâlit 8 secondes après la fin de l'échange (la survoler la ravive). Les boutons restent toujours à la même place, en bas.

Le texte de l'échange s'affiche tout en bas. L'interface se pilote uniquement à la voix (le serveur accepte toujours un message texte `text.input`, utilisé par les tests). La détection de voix combine le volume et un détecteur de voix humaine (Silero, dans le navigateur) : une musique de fond n'ouvre pas de phrase et ne retient pas la tienne, qui se ferme dès que tu te tais. Un son continu pris pour une voix (chanson, télévision) est abandonné au bout de 20 s, avec un message, et devient le bruit de fond à dépasser. Réglages du geste et de l'audio gardé (avant et après l'appui) dans [`push-to-talk.ts`](../apps/web/src/app/call/push-to-talk.ts).

```bash
pnpm stop     # arrêt propre (serveur + workers + sessions enfants)
```

### L'application Kopilia (Mac)

La même page de Kopilia, dans sa propre fenêtre ([`apps/desktop`](../apps/desktop), Tauri). En plus du navigateur, **⌥ droite marche même quand une autre application est devant** (TradingView, par exemple) : l'application écoute le clavier de tout le Mac et transmet à la page les seuls gestes de ⌥ (une autre touche pendant ⌥ n'arrive que comme « autre touche », sans dire laquelle ; rien ne part tant qu'aucun ⌥ n'est enfoncé).

```bash
pnpm app      # construit apps/desktop/src-tauri/target/release/bundle/macos/Kopilia.app (Rust et Xcode requis)
```

- Elle affiche la page servie par le serveur (http://127.0.0.1:4317). **S'il ne tourne pas, elle le lance** (`scripts/start.sh`, comme `pnpm start`, avec le PATH de ton terminal) et l'attend : en attendant, la boule de Kopilia et sa galaxie se réveillent à l'endroit exact où la page les reprendra ([`waiting.ts`](../apps/web/src/app/orb/waiting.ts), le même dessin que l'écran). Quitter l'application ne l'arrête pas : alertes et Telegram continuent ; `pnpm stop` l'arrête. Sa sortie : `~/Library/Logs/Kopilia/serveur.log`. Une nouvelle version de la page est en ligne au prochain rechargement, sans reconstruire l'application.
- **Une icône dans la barre des menus** dit où il en est, même fenêtre cachée : rond vide (serveur arrêté, ou micro pas encore ouvert), rond plein (prêt), vert (il t'écoute), rond pointé (il réfléchit), bleu (il parle). Son menu : afficher Kopilia, autoriser ⌥ droite partout, démarrer, relancer ou arrêter le serveur, journal du serveur, **ouvrir Kopilia avec le Mac** (à cocher sur l'application rangée à sa place définitive : elle s'ouvre alors sans fenêtre), quitter.
- **Fermer la fenêtre la cache** : Kopilia continue d'entendre ⌥ droite et de parler. L'icône du Dock ou « Afficher Kopilia » la font revenir.
- **Telegram prend le relais quand tu t'absentes**, plus quand la fenêtre est cachée : dans l'application, elle l'est souvent alors que tu es là. Tu es absent quand le Mac est verrouillé, ou sans clavier ni souris depuis 3 minutes, dans n'importe quelle application (aucune autorisation : macOS ne donne que le temps écoulé). Ce que Kopilia gardait pour plus tard part alors aussi sur Telegram, comme avec un onglet caché dans le navigateur. Pour un essai : `open Kopilia.app --env KOPILIA_AWAY_AFTER=8` (secondes).
- Le son et le micro s'ouvrent dès l'ouverture, sans geste dans la page. Le micro continue d'entendre fenêtre au second plan ou cachée (mesuré : ta voix à −15 à −28 dB, aucun trou). macOS n'ouvre toutefois pas le micro d'une page jamais montrée : ouverte avec le Mac, la fenêtre apparaît le temps que le micro s'ouvre (une seconde, serveur prêt), puis se range.
- Options : `open Kopilia.app --args --url http://127.0.0.1:4398/` (une autre adresse), `--repo <dossier>` (par défaut celui où elle a été construite), `--no-server` (ne jamais lancer de serveur), `--hidden` (ouverture avec le Mac). Kopilia déjà ouverte : `open -n Kopilia.app --args --restart-server` relance son serveur, `--hidden` cache sa fenêtre. Une seule Kopilia tourne à la fois.
- Au premier lancement, macOS demande le micro, puis **Surveillance de l'entrée** (Réglages Système › Confidentialité et sécurité) : active Kopilia. macOS ferme alors l'application, rouvre‑la. Sans cette autorisation, ⌥ droite ne marche que la fenêtre de Kopilia devant.
- Elle est signée avec ton certificat « Apple Development » s'il y en a un (sinon, signature locale) : macOS lie les autorisations à la signature, elles tiennent alors d'une version à l'autre. Un autre certificat : `APPLE_SIGNING_IDENTITY="…" pnpm app`.
- **⌥ Espace** passe aussi par l'écoute du clavier. Sans elle, l'application tente un raccourci global ⌥ Espace, mais macOS 15 et suivants bloquent ou ignorent souvent les raccourcis faits du seul ⌥.
- Journal : `~/Library/Logs/Kopilia/kopilia.log` (démarrage, autorisation, écoute du clavier, serveur, état de l'icône ; jamais les touches).
- macOS 27 refuse les bibliothèques passées à `strip` par Rust 1.92 : le profil `release` le désactive ([`Cargo.toml`](../apps/desktop/src-tauri/Cargo.toml)).

## 5. Usage

- **Projets.** L'espace de travail est `~/Documents` (première racine de `KOPILIA_PROJECT_ROOTS`) ; chaque sous‑dossier est un projet. Rien à sélectionner : nomme le projet dans ta demande (« dans Kopilia, lance les tests ») ; Kopilia retrouve le dossier ou te demande lequel. Sans projet, l'ouvrier travaille dans Documents même. Les chemins hors racines (y compris via lien symbolique) sont refusés, et les paquets macOS (`.mindnode`…) ne comptent pas comme projets.
- **Un dialogue rapide, des agents puissants.** Kopilia répond avec un modèle rapide (Haiku) et délègue tout ce qui demande du travail, sans demander la permission :
  - **agents** (`ask_agent`, Sonnet ; Opus pour une analyse approfondie) : recherche web poussée (programme d'un cinéma, horaires, prix, comparaisons), lecture et analyse d'un projet. Ils ne modifient **jamais** rien, donc aucune confirmation. Jusqu'à 3 en parallèle ; la conversation continue pendant qu'ils travaillent.
  - **ouvriers** (`start_task`, Opus) : ils **agissent** dans un projet (fichiers, commandes, git). Une confirmation s'affiche à l'écran avant l'exécution (refus ou délai de 2 min = rien n'est fait). **Plusieurs projets avancent en même temps** : une tâche à la fois par projet (deux ouvriers ne touchent jamais les mêmes fichiers), trois au plus. Une tâche lancée dans Documents même compte pour tous les projets. Chaque travail affiché à l'écran porte le nom de son projet.
  - **rapport automatique** : quand un agent ou un ouvrier termine, Kopilia prend la parole de lui‑même, dès que personne ne parle (jamais en coupant la conversation).
    - Si le résultat est court (une réponse rapide, environ 80 mots hors sources), ou si c'est un échec, il le dit directement.
    - Sinon, il annonce seulement que la tâche est terminée et te demande si tu veux le résultat maintenant. Dis « oui » et il le résume ; « plus tard » et il n'insiste pas, il le garde pour quand tu le demanderas.
    - Le brief de veille suit toujours cette seconde voie. Le texte apparaît marqué « Résultat d'agent ». Après avoir raccroché, il s'affiche sans être dit.
  - « Où en es‑tu ? » consulte l'état, « Concentre‑toi sur X » transmet une consigne au travail en cours (il la reçoit dès la fin de son étape en cours ; plusieurs consignes s'ajoutent), « Annule » coupe le travail **et ses processus enfants**.
  - Modèles réglables dans `.env` : `KOPILIA_DIALOGUE_MODEL`, `KOPILIA_AGENT_MODEL`, `KOPILIA_DEEP_MODEL`, `KOPILIA_CLAUDE_MODEL`, repli `KOPILIA_FALLBACK_MODEL` (voir `.env.example`). L'effort du dialogue (`KOPILIA_DIALOGUE_EFFORT`) est « low » par défaut : Kopilia répond vite, sans hériter de l'effort réglé dans Claude Code.
- **Reprendre une conversation.** L'identifiant de session Claude est persisté et la reprise via `--resume` est câblée côté serveur (`SessionService`), mais l'interface ouvre aujourd'hui une **nouvelle conversation à chaque connexion** (page rechargée ou serveur redémarré).
- **Veille économique (brief).** « Fais-moi le point macro », « Fais-moi le wrap », « Lance la veille » : un agent (Sonnet 5.5, réglable) rédige en quelques minutes un brief sourcé sous forme de **session wrap**, à la manière des wraps de séance d'investingLive. Il ne couvre que la période écoulée **depuis le brief précédent** (à défaut, les dernières 24 heures, depuis vendredi soir le week-end) et ne dit que ce qui est nouveau : le contexte déjà connu (« la Fed envisage de remonter ses taux ») n'est pas répété.
  - **Rubriques.** Un titre qui résume les deux faits marquants, les séances couvertes, puis : **En bref** (trois ou quatre phrases, dites par Kopilia) ; **Titres** (une ligne par nouvelle : décisions et déclarations de banques centrales, chiffre publié contre prévision, devise qui bouge…) ; **Marchés** (devise la plus forte et la plus faible, or, WTI, taux US à 10 ans, actions) ; **Le récit** (ce qui a fait bouger les marchés et pourquoi) ; **À suivre** (rendez-vous en heure de Paris) ; **Sources**.
  - **Recherche.** L'agent part des wraps et des titres d'investingLive, vérifie les chiffres importants à la source et lit le brief précédent pour ne rien redire. Une période calme donne un wrap court.
  - Le brief complet s'ouvre avec le bouton **Brief** en haut ou le lien « Lire le brief ». Pour détailler une rubrique, demande-le : Kopilia relit le brief (`get_brief`).
  - **Deux wraps automatiques, du lundi au vendredi** (`KOPILIA_BRIEF_TIMES`, `07:00,12:30` par défaut) :
    - à **7 h**, la fin de séance américaine et la séance asiatique (le lundi, depuis le wrap du vendredi midi : fin de semaine américaine, week-end, ouverture de l'Asie) ;
    - à **12 h 30**, la matinée de Londres, avant les chiffres américains de 14 h 30 et l'ouverture de New York.
    - Rien le week-end, marchés fermés. Un wrap manqué (Mac en veille, serveur arrêté) est rattrapé **dans l'heure** (jusqu'à 8 h pour celui de 7 h) ; un échec est retenté deux fois, à 10 min d'intervalle. Au-delà, il saute : le wrap suivant couvre toute la période depuis le dernier wrap fait (au plus quatre jours, sinon les dernières 24 heures). Un brief demandé moins d'une heure avant l'heure prévue tient lieu de wrap.
    - Kopilia te résume le dernier wrap **dès que tu décroches**, une seule fois (un wrap plus ancien jamais dit n'est plus annoncé, mais il reste dans `data/briefs/`).
  - Chaque brief est aussi enregistré en Markdown dans `data/briefs/` (lisible hors de Kopilia).
  - Les wraps programmés exigent que `pnpm start` tourne et que le Mac soit éveillé (ou réveillé, p.ex. `sudo pmset repeat wakeorpoweron MTWRF 06:55:00`).
  - Le calendrier Forex Factory (ci‑dessous) donne à l'agent les annonces publiées pendant la période (dont il cherche le chiffre) et celles à venir (rubrique À suivre). Le wrap programmé attend sa mise à jour (celle de 6 h le matin, de 12 h à midi), une minute au plus.
- **Calendrier économique (Forex Factory).** « Quelles annonces aujourd'hui ? », « Qu'est-ce qu'il y a d'important cette semaine sur le dollar ? », « À quelle heure sort le NFP ? » : Kopilia répond tout de suite à partir du calendrier Forex Factory gardé en local (outil `economic_calendar`). Pour chaque annonce : l'heure, la devise, l'impact, la prévision et le chiffre précédent.
  - **Fraîcheur.** Le flux officiel (`nfs.faireconomy.media`, semaine en cours) est récupéré trois fois par jour, dans l'heure qui suit 6 h, 12 h et 18 h (annonces ajoutées ou déplacées, prévisions révisées) ; un rendez-vous manqué attend le suivant. Une question ou un wrap le met quand même à jour si ce n'est pas fait depuis le dernier rendez-vous. Kopilia n'envoie jamais plus d'une requête par 5 minutes (Forex Factory bloque au‑delà). Si Forex Factory est injoignable, les dernières données restent servies, avec une mise en garde.
  - **Heures.** Le flux est en heure de New York ; tout est converti dans le fuseau du Mac (heure de Paris), changements d'heure compris.
  - **Limites.** Le flux ne couvre que la semaine en cours (dimanche à samedi) et ne donne pas le chiffre publié. Pour un résultat déjà sorti, Kopilia confie la recherche à un agent, qui le compare à la prévision.
  - Les agents et la veille lisent la semaine complète dans `data/calendar/forexfactory.md`. `KOPILIA_FF_CALENDAR_URL` vide désactive le calendrier.
- **Cours en direct (MetaApi).** « Donne-moi le dernier prix de l'euro-dollar », « Où en est le Nasdaq ? », « Le Dow et l'or ? » : Kopilia lit le prix à l'instant sur ton compte MetaTrader, via [MetaApi](https://metaapi.cloud) (outil `market_price`, six produits au plus par demande). Il le dit arrondi comme un trader et signale un marché fermé, avec l'heure de la dernière cotation.
  - **Mise en place.** Crée le compte dans l'interface MetaApi : login MetaTrader, mot de passe et nom du serveur du courtier. Le mot de passe **investisseur** suffit : lecture seule, aucun ordre possible. Le compte doit être **déployé**. Dans `.env`, mets ensuite `KOPILIA_METAAPI_TOKEN` (le jeton d'API) et, si tu as plusieurs comptes, `KOPILIA_METAAPI_ACCOUNT_ID`. Relance Kopilia, puis vérifie avec `pnpm doctor` (ligne « MetaApi »).
  - **Symboles.** Chaque courtier nomme les produits à sa façon (NAS100, US100 ou USTEC ; EURUSD.m, XAUUSDm…). Kopilia retrouve le bon dans la liste du courtier, à partir du nom courant (Nasdaq, Dow Jones, S&P 500, DAX, CAC 40, or, argent, pétrole, gaz, bitcoin…) ou du code usuel (EURUSD, AAPL). Introuvable : il propose les symboles les plus proches.
  - **Prix.** Kopilia donne le cours vendeur (bid), celui des graphiques MetaTrader, et garde aussi le cours acheteur et le spread. Le compte et la liste des symboles sont relus toutes les 10 minutes et toutes les heures ; seul le prix est redemandé à chaque question.
  - **Délai.** La première demande d'un produit prend quelques secondes, le temps que MetaApi s'abonne à ses cotations. La toute première demande après le démarrage peut prendre une vingtaine de secondes. Ensuite, la réponse vient en moins d'une seconde pendant 12 minutes.
  - **Historique (outil `market_history`).** « Prix d'ouverture de l'euro-dollar aujourd'hui ? », « Clôture du Nasdaq vendredi dernier ? », « Le Nasdaq à l'ouverture de Wall Street hier ? », « Plus haut et plus bas de l'or cette semaine ? » : ouverture, plus haut, plus bas, clôture (ou dernier prix) et variation. Ça marche pour un jour, une semaine, un mois, une plage de jours (366 au plus) ou une séance.
    - **Le jour.** C'est la journée du courtier, celle des bougies quotidiennes de MetaTrader : chez la plupart des courtiers MetaTrader (serveur en GMT+2 ou +3), de 23 h la veille à 23 h, heure de Paris. Pour un jour seul, l'outil donne l'heure du plus haut et du plus bas (« 23 h 10 la veille » si c'était la veille au soir) ; sur plusieurs jours, le jour des extrêmes et le détail jour par jour. Un jour sans cotation (fin de semaine, férié) donne la dernière séance avant lui.
    - **Les séances.** Asie (de l'ouverture de Tokyo à celle de Londres), Londres (8 h – 16 h 30 à Londres) et New York (9 h 30 – 16 h à New York : l'ouverture de Wall Street). Elles sont calculées sur les bougies de 5 minutes, changements d'heure compris.
    - **Délai.** La réponse arrive en 0,4 à 3 secondes.
  - **Agents.** Les agents de recherche et l'agent de veille ont les mêmes outils, par un serveur MCP à eux (« kopilia », [`agent-server.ts`](../apps/server/src/mcp/agent-server.ts)). Seul le serveur Kopilia parle à MetaApi. L'agent reçoit un jeton qui n'ouvre que la lecture des cours : ni le jeton MetaApi, ni les tâches, ni la mémoire. Une analyse des cours (tendance, comparaison sur plusieurs jours) part donc chez un agent qui calcule sur les chiffres exacts du courtier, sans passer par le web. L'agent de veille y prend les niveaux de sa rubrique Marchés.
  - **Secret.** Le jeton ne quitte pas le serveur : il n'est transmis ni à Claude, ni aux agents, ni aux ouvriers, et n'apparaît dans aucun journal. Sans jeton, l'outil est désactivé et un cours se cherche sur le web.
- **Documents.** Glisse un fichier dans la fenêtre, clique sur le trombone (**Joindre**) ou colle une capture d'écran (Cmd+V) : il s'affiche en vignette au-dessus des boutons, puis part avec ta **phrase suivante**, qui dit quoi en faire (« Résume-moi ça », « Qu'est-ce que ça change pour l'or ? »). Une fois la phrase dite, la vignette disparaît ; le × la retire avant.
  - **Formats.** PDF, images (PNG, JPEG, GIF, WebP ; HEIC et TIFF convertis en JPEG par `sips`), texte (TXT, Markdown, CSV, JSON…), Word, RTF, OpenDocument et HTML (convertis en texte par `textutil`). 32 Mo au plus. Pas d'Excel : exporte-le en CSV.
  - **Court ou long.** Un document court (une image, un PDF de 10 pages au plus, un texte de 40 000 caractères au plus) est lu directement par Kopilia, qui répond aussitôt et peut y revenir dans la conversation. Un document plus long n'entre pas dans la conversation (il y serait renvoyé à chaque phrase et ralentirait toutes les réponses) : Kopilia le confie à un agent (`ask_agent` avec `documents`), qui le lit en entier et rapporte. Kopilia peut aussi confier un document court à un agent pour une analyse approfondie ou des recherches à croiser.
  - Les fichiers restent sur le Mac, dans `data/documents/`. Un document déposé est lié à la conversation ouverte : si la page se reconnecte avant que tu aies parlé, dépose-le à nouveau.
- **Mémoire.** Quand tu donnes à Kopilia une information durable sur toi (« j'habite à Lyon », tes goûts, tes habitudes), il la retient (`remember`) ; elle figure ensuite dans le contexte de chaque conversation **et de chaque agent** (« le cinéma près de chez moi » marche alors sans rien préciser). « Oublie mon adresse » l'efface (`forget`). Stockage SQLite FTS5, indépendant du contexte du CLI.
- **Tableau de bord (graphiques à la voix).** « Montre-moi l'euro-dollar », « mets le Nasdaq à côté, en 1 heure », « ajoute un suivi avec l'or et le Dow », « passe en 5 minutes », « enlève l'or du suivi », « ferme l'euro-dollar », « efface tout le tableau de bord » : des encarts s'ouvrent dans les marges, de part et d'autre de l'orbe (un nouveau du côté le moins chargé ; chacun garde ensuite sa marge, fermer un encart ne déplace pas les autres ; sur un écran étroit, au-dessus), dans le même habillage que les tâches, et la galaxie les rattache à l'orbe d'un fil. Un **graphique** montre les bougies du compte MetaTrader (de 1 minute à 1 jour ; zoom, défilement, passé chargé en remontant le temps ; bougie en cours animée par les cotations ; heures de Paris). Tout tient dans une ligne d'en-tête (nom courant, prix du moment, variation du jour, repère « fermé » quand le marché l'est) et les boutons d'unité en bas : le reste de l'encart est au graphique. Ni symbole technique du courtier, ni nom du compte, ni heure de cotation à l'écran. Un **suivi** liste les prix de plusieurs produits. Douze encarts au plus : deux par marge l'un sous l'autre, les suivants s'empilent sur le dernier, un peu décalés (un clic fait passer devant celui de dessous) ; le même produit ne s'ouvre pas deux fois. Tout se fait aussi à la main : boutons d'unité, ×, « Tout fermer », Échap. Le tableau de bord est gardé en base : un rechargement, un redémarrage ou un autre écran le retrouvent tel quel. Quand des encarts sont affichés, Kopilia sait lesquels (une note devant ta phrase, avec leur identifiant) : « qu'est-ce qu'il y a à l'écran ? » répond sans outil, « ferme l'or » sans graphique de l'or te le dit.
  - **Vue, comme sur TradingView.** Glisser l'**axe des prix** vers le bas tasse les bougies en hauteur, vers le haut les étire (la molette sur cet axe fait de même autour du prix visé) ; glisser l'**axe du temps** vers la droite élargit les bougies, vers la gauche les resserre. Tirer le graphique vers la gauche laisse de l'espace à droite de la dernière bougie (six bougies d'avance par défaut, jusqu'aux quatre cinquièmes de la vue) : elle ne colle plus à l'axe des prix, et l'espace garde sa largeur quand on zoome. Glisser le graphique en hauteur le déplace verticalement. Dès qu'on règle la hauteur, l'échelle des prix ne suit plus les bougies : « auto », dans le coin des axes, s'estompe ; un clic dessus, ou un double-clic sur l'axe des prix, la rend automatique. Double-clic sur l'axe du temps : largeur et avance par défaut. Changer de produit ou d'unité de temps remet l'échelle en automatique.
  - **Rendu.** Dessiné à la main sur un canvas, sans bibliothèque de graphiques ([`candle-chart.ts`](../apps/web/src/app/dashboard/candle-chart.ts)) : bougies, axes des prix et du temps, ligne du dernier prix, réticule avec la bougie survolée (ouverture, plus haut, plus bas, clôture), zoom à la molette ou au pincement, défilement à la souris ou au doigt, double-clic pour revenir au présent. Aux couleurs du thème, sombre ou clair, net sur Retina. Chaque graphique se **redimensionne** par la poignée dans son coin, vers le centre de l'écran, sans autre limite qu'une marge de 16 px au bord de la fenêtre (une poignée passée sous la discussion réapparaît par-dessus quand le pointeur s'en approche ; la discussion prend alors un fond léger pour rester lisible) ; le bouton **Agrandir** de l'en-tête le met presque en plein écran, et un second clic, un double-clic sur l'en-tête ou Échap lui rendent sa place et sa taille. Il remplit l'encart à la même échelle (plus de bougies en largeur, plus d'air en hauteur), et la taille est gardée sur cet écran. Chaque encart se **déplace** par son en-tête (glisser-déposer) : il sort de sa marge et se pose où on le lâche, devant les autres (ils peuvent se chevaucher, le dernier déplacé passe devant), sans jamais sortir de l'écran ; la marge qu'il quitte se resserre, et la galaxie le rattache par le bord qui regarde l'orbe. Double-clic sur l'en-tête : il revient dans sa marge. La position est gardée sur cet écran, comme la taille. Sur un écran étroit, tout reste dans la colonne.
  - **Cotations.** Poussées par MetaApi sur sa connexion **WebSocket**, tant qu'un écran est connecté et qu'un encart montre le produit, et toujours pour un produit qui a une alerte (page fermée comprise). Elles arrivent à l'écran environ 0,1 s après leur heure de cotation (mesuré sur le compte démo), sans aucune demande de prix : le quota de requêtes de MetaApi reste libre. La connexion s'ouvre au premier encart (une dizaine de secondes, synchronisation du compte comprise) et reste ouverte ; le SDK officiel de MetaApi ([`metaapi-stream.ts`](../apps/server/src/market/metaapi-stream.ts)) se reconnecte et renouvelle les abonnements de lui-même.
    - **En secours**, un produit est interrogé comme avant (toutes les 2 secondes, toutes les 15 secondes marché fermé) : à l'ouverture de son encart, le temps que le flux démarre ; quand le flux ne dit plus rien de lui depuis 15 secondes (connexion coupée, marché calme ou fermé) ; s'il est refusé par le flux. Une connexion ratée est retentée de plus en plus tard (15 s, puis jusqu'à 5 min). `KOPILIA_METAAPI_STREAM=0` revient à l'interrogation seule.
    - Les bougies sont celles du courtier (1 000 au plus par paquet) ; à chaque nouvelle bougie, la précédente est reprise du courtier (clôture exacte).
  - **Analyse technique.** Sur la ligne du bas de chaque graphique, à droite des unités de temps : les outils de tracé et le menu des indicateurs.
    - **Indicateurs** : autant de moyennes mobiles et de RSI qu'on veut (dix au plus par graphique), chacun réglé dans le panneau Indicateurs. Une **moyenne mobile** a un type (simple MM, exponentielle MME, pondérée MMP, lissée de Wilder MML, de Hull HMA), une longueur (1 à 500 bougies) et une source (clôture, ouverture, plus haut, plus bas, (H + B) / 2, (H + B + C) / 3, (O + H + B + C) / 4). Un **RSI** (Wilder) a une longueur, une source, ses seuils de surachat et de survente (70 et 30 d'usage) et, s'il le faut, sa moyenne (ligne de signal en pointillés, de n'importe quel type). Chacun a sa couleur (neuf teintes, adaptées au thème) et son épaisseur (1 à 4) ; l'œil le masque sans perdre ses réglages. « + Moyenne mobile » et « + RSI » ouvrent les réglages d'un nouvel indicateur ; la ligne « Rapide » ajoute en un clic les plus courants (MM 20, 50, 200, MME 9, 21, RSI 14). Noms et valeurs en haut à gauche, sur la bougie survolée, sinon la dernière. Ils restent quand on change d'unité de temps ou de produit. À la voix : « ajoute une exponentielle 50 et une simple 200 », « mets le RSI avec sa moyenne 14 », « passe la moyenne 50 en exponentielle », « RSI à 80 / 20 », « masque la 200 », « le RSI de l'or en 1 heure ? » (`market_indicators`, calculé comme à l'écran, sur la bougie en cours et la dernière close).
    - **Tracés** : ligne horizontale (un clic), oblique (deux clics, ou glisser ; prolongée vers la droite) et zone (deux coins, ou glisser). **Maj** maintenu, comme sur TradingView, ramène l'oblique à l'horizontale (exactement au prix du premier point), à 45° ou à la verticale, selon où est le pointeur ; ça vaut aussi quand on tire un bout d'une oblique existante. Une verticale marque un instant (« ligne verticale le 4 nov. 02:15 ») et n'est jamais prolongée. Un clic sur un tracé le sélectionne : on le déplace par son corps, un point ou un bord ; Suppr ou la corbeille l'efface ; la flèche prolonge une oblique ou une zone vers la droite (ou l'arrête). Échap annule l'outil ou la sélection sans fermer l'encart. À la voix : « mets une résistance à 2 680 », « trace la zone 2 650 – 2 660 », « trace une oblique entre le plus bas de ce matin et celui d'hier », « monte-la à 2 690 », « efface les tracés de l'or ».
    - **Aimant**, comme sur TradingView : le bouton en U, à gauche des outils, passe de faible (le prix colle à l'ouverture, au plus haut, au plus bas ou à la clôture de la bougie visée quand on en est près) à fort (toujours au plus proche des quatre) puis désactivé. **Cmd** (Ctrl hors Mac) maintenu l'inverse le temps du tracé : désactivé, il devient fort ; actif, il se coupe. En traçant, le réticule montre le prix retenu, et un cercle sur la bougie quand l'aimant colle. Le choix est gardé sur cet écran.
    - Un tracé appartient au **produit**, pas à l'encart : il se retrouve dans toutes les unités de temps, après avoir fermé puis rouvert le graphique, et sur tous les écrans. Gardé en base avec un identifiant stable, il est listé à Kopilia dans la note des encarts (« d_3f2a1b ligne à 2 680,50 « résistance » »). Une oblique se calcule en temps de marché (en bougies) : elle reste droite d'une unité de temps à l'autre, malgré les nuits et les week-ends.
    - Les calculs (cinq moyennes, RSI de Wilder, sources, position d'un instant parmi les bougies, prix d'une oblique) sont dans [`technical.ts`](../packages/contracts/src/technical.ts), partagés par l'écran et le serveur : les alertes voient exactement ce que montre le graphique.
  - **Alertes**, comme sur TradingView : à un prix, ou sur une ligne tracée (horizontale ou oblique ; pas sur une zone ni une verticale, qui n'ont pas de prix).
    - **Les poser** : clic droit sur une ligne (« Ajouter une alerte… ») ou sur un prix vide (« Alerte à 4 016,83… », ou une ligne horizontale à ce prix) ; le **« + »** qui suit le réticule contre l'axe des prix ; **Alt+A** (sur la ligne sélectionnée, sinon au prix sous le pointeur) ; ou à la voix : « préviens-moi si l'or casse ma résistance », « mets une alerte à 21 000 sur le Nasdaq, et regarde le RSI quand elle part ».
    - **Les régler** : le sens (franchit à la hausse, à la baisse, ou les deux ; une alerte de prix au-dessus du cours attend la hausse, au-dessous la baisse) ; quand elle part (une seule fois, puis elle s'arrête ; une fois par bougie au plus ; ou seulement quand une bougie clôture au-delà, dans l'unité du graphique où elle est posée) ; une **consigne pour Kopilia**, qu'il suivra quand elle part (« dis-moi si la cassure tient »). Toucher le niveau compte.
    - **À l'écran** : une alerte de prix est une ligne orange en pointillés, avec son prix sur l'axe ; on la glisse pour la déplacer. Une ligne qui porte une alerte a une petite cloche. La cloche de la barre d'outils liste les alertes du produit (suspendre, réactiver, régler, supprimer) et passe en orange quand il y en a de surveillées. Une alerte suit sa ligne : la déplacer la réarme là où est le prix (passer la ligne de l'autre côté du prix ne la déclenche pas) ; effacer la ligne retire l'alerte ; une oblique non prolongée expire à son bout, et repart si on la prolonge.
    - **Surveillées par le serveur**, même page fermée, sur les cotations poussées, et sur le plus haut et le plus bas de la bougie d'une minute, qui gardent une mèche plus brève que l'intervalle des cotations (½ s) ; une alerte sur clôture relit la bougie close chez le courtier. Le côté du prix est gardé en base : une alerte franchie pendant que le serveur était arrêté part à son retour, en le disant.
    - **Quand elle part** : un bandeau en haut de l'écran, deux notes, la ligne qui clignote, et une notification du navigateur si la page est cachée (permission demandée à la première alerte posée). En appel, Kopilia l'annonce dès qu'il a fini sa phrase (elle passe devant les autres rapports), puis suit la consigne. Sans écran ouvert, une notification du Mac (`KOPILIA_ALERT_NOTIFY=0` pour s'en passer) ; au décroché suivant, Kopilia commence par « Pendant ton absence… » (déclenchements des dernières 24 h).
    - Gardées en base (tables `monitoring_rules` et `monitoring_events`), identifiant stable (`a_…`) ; vingt surveillées au plus par produit ; arrêtées depuis un mois, retirées au démarrage. Code dans [`apps/server/src/alerts/`](../apps/server/src/alerts/).
  - **Outils** `panel_open`, `panel_update`, `panel_close`, `chart_draw`, `chart_move`, `chart_erase`, `chart_drawings`, `alert_create`, `alert_list`, `alert_update`, `alert_delete` (dialogue seulement) et `market_indicators` (dialogue et agents) ; code dans [`apps/server/src/dashboard/`](../apps/server/src/dashboard/), [`apps/server/src/market/quote-feed.ts`](../apps/server/src/market/quote-feed.ts) et [`apps/web/src/app/dashboard/`](../apps/web/src/app/dashboard/).
- **Apprentissage (Kopilia s'améliore d'une fois sur l'autre).** Inspiré de la boucle d'apprentissage de [Hermes Agent](https://github.com/NousResearch/hermes-agent) : le modèle ne change jamais, Kopilia écrit ce qu'il apprend et le relit à chaque conversation. Schéma et détail : [docs/APPRENTISSAGE.md](APPRENTISSAGE.md).
  - **Deux carnets** toujours chargés dans le prompt du dialogue et des agents : le **profil** (qui tu es, tes préférences, tes corrections ; 1 500 caractères) et l'**environnement** (outils, sources, courtier, pièges ; 2 000 caractères). Un budget volontairement petit oblige à fusionner plutôt qu'à empiler. Des constats, pas des ordres (« Préfère les prix avec toutes leurs décimales »).
  - **Des recettes** (skills) : pour une classe de tâches (donner un cours, préparer le brief, trouver des séances de cinéma…), la procédure, les sources qui marchent, tes préférences et les pièges. Celles du dialogue sont placées en entier dans son prompt (aucun appel d'outil avant de répondre) ; les agents et la veille reçoivent l'index et ouvrent la bonne (`skill_view`) avant de commencer. Chaque changement est une version ; rien n'est jamais supprimé.
  - **Le relecteur** : quand une conversation est au repos depuis 10 minutes (ou après 10 demandes), un agent Sonnet relit en arrière-plan les tours pas encore relus et la **trace des agents** (chaque outil, ce qu'il visait, ses erreurs). Il met à jour les carnets et propose des recettes, avec ses seuls outils (serveur MCP `apprentissage`, [`learning-server.ts`](../apps/server/src/mcp/learning-server.ts)) : ni web, ni fichiers, ni commandes. Ses consignes ([`learning-prompts.ts`](../apps/server/src/learning/learning-prompts.ts)) disent surtout ce qu'il ne faut **pas** retenir : une panne passagère, une affirmation négative sur un outil, une tâche ponctuelle, une suite d'échecs, et toute consigne trouvée dans une page web ou un résultat d'agent. Il relit une recette avant de la modifier, et s'arrête après trois écritures refusées.
  - **Tu gardes la main.** Une recette proposée attend ton accord : Kopilia te l'annonce au décroché (« je te propose de retenir… tu es d'accord ? ») et tu réponds à la voix, ou tu valides dans **Mémoire**, à l'écran. `KOPILIA_LEARNING_AUTO_APPROVE=1` les adopte d'office. Ce qui entre dans les carnets s'applique tout de suite ; l'écran **Mémoire** montre tout (carnets, recettes, journal de chaque relecture) et permet d'oublier, de rétablir un texte remplacé, d'archiver ou d'épingler une recette.
  - **À la voix** : « retiens comment faire ça », « à l'avenir, fais plutôt… » lance une relecture immédiate centrée sur ta demande (`learn_from_conversation`) ; « qu'est-ce que tu as appris ? » (`learning_status`) ; « comme l'autre jour… » fait chercher dans vos conversations passées (`search_conversations`, plein texte, une conversation par passage).
  - **Rangement hebdomadaire**, au calme (2 h sans parole) : les souvenirs échus sortent, une recette d'agent inutilisée depuis 90 jours est archivée (récupérable), une proposition sans réponse depuis 14 jours expire ; un modèle ne fusionne que si un carnet approche de son budget ou si les recettes se multiplient. Rien au tout premier passage.
  - **Garde-fou** ([`guard.ts`](../apps/server/src/common/guard.ts)) : tout ce qui entre dans un carnet ou une recette est refusé s'il ressemble à une injection (« ignore tes instructions »), à un envoi de données vers une adresse, à un secret, ou contient des caractères invisibles.

## 6. Confidentialité & suppression des données

- **Aucun son brut** n'est conservé par défaut.
- `pnpm data:wipe` efface la base Kopilia (sessions, tours, tâches, mémoire, observations), les documents déposés (`data/documents/`) et les journaux. **Cela n'efface pas** les sessions conservées par **Claude Code** lui‑même (ses propres fichiers sous `~/.claude`) : c'est un historique **indépendant**, à gérer séparément.
- **Récupérer de l'espace disque** : supprimez `models/` (plusieurs centaines de Mo) ; `pnpm models:fetch` les re‑télécharge.
- Secrets et identifiants de connexion sont **exclus** de la mémoire et des journaux (on ne journalise que des noms d'état).

## 7. Architecture

```
Navigateur (Angular)  ──HTTP amorçage──▶  NestJS (loopback)
      │  WebSocket (contrôle JSON + audio PCM binaire cadré)   │
      ▼                                                        ├─▶ whisper.cpp (STT FR)        ─ worker stdio
  micro 16 kHz + VAD / lecture PCM / barge‑in                  ├─▶ Kokoro‑82M (TTS ff_siwis)   ─ worker stdio
                                                               ├─▶ claude -p stream-json (dialogue)  ─ sous‑processus
                                                               ├─▶ claude -p (worker de tâche)       ─ sous‑processus
                                                               └─▶ SQLite (sessions, tours, jobs, mémoire FTS5)
```

Monorepo pnpm : [`packages/contracts`](../packages/contracts) (protocole partagé), [`apps/server`](../apps/server) (NestJS), [`apps/web`](../apps/web) (Angular), [`workers/`](../workers) (whisper, kokoro, doubles de test), [`scripts/`](../scripts), [`docs/`](.). Contrats d'événements : [docs/CONTRACTS.md](CONTRACTS.md).

La détection de voix (VAD) se fait dans le navigateur ([`push-to-talk.ts`](../apps/web/src/app/call/push-to-talk.ts)) : le volume, plus le modèle Silero v6 exécuté par onnxruntime-web ([`silero.ts`](../apps/web/src/app/audio/silero.ts) ; modèle et moteur servis en local, chargés au premier appel ; s'ils manquent, le volume seul décide). Whisper ne reçoit que des énoncés déjà découpés.

- **Serveur.** La passerelle WebSocket ([`gateway/`](../apps/server/src/gateway)) orchestre ; à côté d'elle, une pièce par rôle : la connexion (`conn.ts`), la lecture des messages (`messages.ts`), la parole d'un tour (`speech-turn.ts`), la file des rapports d'agents (`report-queue.ts`). Les outils MCP de chaque rôle (dialogue, agents, relecteur) sont décrits à un seul endroit ([`mcp/catalog.ts`](../apps/server/src/mcp/catalog.ts)) ; les routes de l'écran et l'API interne sont gardées par `SessionGuard` et `InternalAuthGuard`. Les services émettent des événements typés ; les workers vocaux passent par `WorkerLink` (relance après une panne).
- **Web.** Un store par domaine (travaux, tableau de bord, mémoire, brief, documents) derrière la façade [`KopiliaService`](../apps/web/src/app/kopilia.service.ts) ; l'application ne garde que la coquille (orbe, barre d'appel, transcription, notifications). Les fonctions de calcul (placement des encarts, bougies, phase de l'appel) sont pures et testées sans navigateur.

## 8. Décisions d'implémentation (réversibles)

- **pnpm workspaces** + build **tsc** (pas de nest‑cli) : léger, sans magie.
- **better-sqlite3** (synchrone, transactionnel, FTS5) : idéal mono‑processus local.
- **ws** brut attaché au serveur HTTP : contrôle JSON **et** trames binaires sur une même connexion, en‑tête compact de 16 octets.
- **Environnement enfant assaini** pour `claude` : on retire les variables de provider/billing/host afin de forcer le **login d'abonnement**, ainsi que le jeton MetaApi et les jetons de l'API interne (voir [`child-env.ts`](../apps/server/src/session/child-env.ts)). Les noms retirés sont signalés, jamais les valeurs.
- **Coordination par MCP local** : la session de dialogue n'a que la recherche web et les outils `list_folders/ask_agent/start_task/task_status/instruct_task/cancel_task/start_brief/get_brief/economic_calendar/market_price/market_history/remember/forget/skill_view/search_conversations/learn_from_conversation/learning_status/skill_decide/panel_open/panel_update/panel_close`. Un agent a le web et la lecture (plus le dossier `data/calendar`), les recettes et les outils de cours du serveur MCP `kopilia` (`--permission-mode dontAsk`, écriture interdite) ; le relecteur n'a que le serveur `apprentissage` (`--strict-mcp-config`) ; un ouvrier a tous les outils dans le projet visé (`bypassPermissions`, après confirmation). Chaque serveur MCP a son jeton, qui n'ouvre que ses routes de l'API interne ; ceux du relecteur ne valent que pendant sa passe.
- **STT par énoncé avec Whisper large-v3-turbo** (q5_0, 574 Mo) : `whisper-server` est lancé une fois, avec le modèle gardé en mémoire, la flash attention et Metal ; il faut **~0,8 s** entre la fin d'une phrase et son texte sur M3 Pro. Repli automatique sur `whisper-cli` (~1,2 s) si le serveur manque ou tombe.
  - Choix mesuré sur ce Mac face à Base : environ 4 fois moins d'erreurs en français, pour 0,5 s de plus.
  - C'est le même modèle que VoiceInk, et le même fichier (empreinte vérifiée).
- Port **4317** par défaut, loopback only.
- **Qualité du code** : ESLint (règles recommandées, plus les promesses oubliées) et Prettier (largeur 160). Le CSS et les gabarits Angular inclus dans les composants gardent leur écriture compacte (non reformatés). `pnpm check` enchaîne tests, lint, mise en forme et diagnostic.

## 9. Sécurité

Loopback uniquement ; vérification d'origine et d'hôte ; ouverture WS protégée par **jeton de session court**. Chemins hors racines refusés (realpath, anti‑lien symbolique). Permissions normales du CLI conservées ; une action sensible présente l'action exacte + le projet avant exécution ; refus/délai expiré = action bloquée. Aucune relance automatique d'une commande à effets de bord après crash/déconnexion — **les fichiers du dépôt font foi**.
